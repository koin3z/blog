CPU・メモリ・I/Oは、同じ「VMMを一回通る」経路ではない

CPU の実行

大半のゲスト命令はCPU上で直接実行

ゲスト scheduler
プロセス → vCPU
↓
QEMU の vCPU thread
KVM_RUN を呼ぶ
↓
物理CPUで
VMX non-root 実行
↓
捕捉が必要な時だけ VM exit
KVM、必要なら QEMU が処理

ホスト scheduler は vCPU thread → pCPU を割り当てる

メモリの変換

ゲストの「物理」はホストの物理ではない

GVA
Guest Virtual Address
↓ ゲスト page table
GPA
Guest Physical Address
↓ EPT / NPT
HPA
Host Physical Address

ゲストkernelが管理するのは主に
GVA → GPA。GPA → HPA はVMM/CPU側。

virtio I/O の往復

デバイス要求はbackendへ受け渡す

ゲストアプリの read / send
→ ゲストkernel / driver
↓
virtqueue に descriptor
または MMIO / PIO
↓
QEMU / vhost backend
ホストkernel・ファイル・NICへ
↑
used ring を更新
仮想割り込みでゲストへ通知

これは guest syscall の逐語翻訳ではない
