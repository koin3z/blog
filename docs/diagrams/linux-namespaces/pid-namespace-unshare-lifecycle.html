1

親 PID namespace

caller shell

sudo unshare --pid sh

sh 自身は元の PID namespace に残る

新しい namespace は次に作る子へ適用される

2

子 PID namespace

最初の whoami

whoami → PID 1

sh が作る最初の子として新しい namespace へ入る

最初のプロセスなので init process になる

3

子 PID namespace

whoami が終了

PID 1 の終了

子 namespace の init process がいなくなる

この namespace には次のプロセスを作れない

4

親 → 子 namespace

次の fork(2)

fork(2) → ENOMEM

sh が2回目の whoami を作ろうとして失敗する

sh: 2: Cannot fork

原因

sh のゾンビ回収漏れではなく、短命な最初の子が PID 1 になって終了したこと
