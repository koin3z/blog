# デザインシステム

## 構成原則

- 1枚の図に1つの主張を置く
- 読み順を左から右、上から下、中心から外側のいずれか1つに揃える
- 主役のノード、接続、必要な補足を視覚的に分ける
- 同じ階層の要素は寸法、角丸、余白、文字組を揃える
- 飾りよりも関係の判読を優先する
- 図を「背景のないスライド」ではなく、内容に密着した部品として設計する
  - 図全体のタイトル、キッカー、凡例、ページ番号を定型要素にしない
  - 空白は関係やグループを示す範囲だけ残す
  - 1つのノードはタイトルと、必要なら短い補足1行を基本にする

## シンプルさの判定

次のどれかに該当する場合は、透過処理ではなく構成から見直す。

- 上端に図全体のタイトル専用領域がある
- 下端に用途のない広い余白がある
- 大きなカードの中央へ少量の文字だけを置いている
- すべてのカードへ同じアイコン、影、バッジを機械的に追加している
- 角丸、影、グラデーションが関係線より先に目へ入る
- 16:9の寸法を先に選び、余った領域を装飾で埋めている

図から背景を外しただけに見える場合は不合格とする。
ノードと線だけを残しても意味が読める状態を先に作り、装飾は必要な分だけ戻す。

## 透明背景

- `html`、`body`、`#diagram`とその祖先ラッパーは`background: transparent`
- `html`、`body`、`#diagram`とその祖先ラッパーに`background-image`を設定しない
- 原則として`#diagram`を`body`の直接の子にする
- 祖先ラッパーを使う場合は、影、フィルター、マスク、疑似要素、クリッピングを設定しない
- キャンバス全面を覆う白やグレーの背景レイヤーは置かない
- カードと注釈は不透明にしてよい
- 配置先の明暗が不明な場合は、白と`#0F172A`の両方へPNGを重ねて確認する
- 直接ラベルが片方で読めない場合は、選択した主色の淡色で文字の背面だけに必要最小限の不透明な面を置く
- 暗色面への対処に`text-shadow`、CSSアウトライン、`-webkit-text-stroke`を使わない
- 影のオフセット、ぼかし、広がりを含む描画範囲が切れない余白を確保する
- 四隅には常に透明領域を残す
- PNG外周帯の90%以上を完全透過にする
- PNG全体の5%以上を完全透過にする

透過PNGは、アルファチャンネルの有無だけでは判定できない。
アルファ値が全画素`255`なら、RGBA形式でも背景は透過していない。
四隅だけが透過していても全面背景に近い画像は不適合とし、外周帯の透明画素比率も検査する。
キャンバス面積の90%以上を覆う単一の背景板も不適合とする。

## キャンバス

| パターン                   | 寸法の開始範囲     | 外周余白 |
| -------------------------- | ------------------ | -------- |
| 小さな分類、コマンド群     | 480〜840×160〜280  | 16〜28px |
| 3〜5段階の横フロー         | 720〜1000×200〜360 | 20〜36px |
| 4〜7要素のハブ・スポーク   | 800〜1100×520〜760 | 28〜44px |
| 3〜5層のレイヤー、縦フロー | 640〜900×360〜700  | 24〜40px |
| 3〜4列の比較               | 720〜1000×280〜620 | 24〜40px |

- 表の寸法はCSS上の論理寸法であり、高密度PNGは論理寸法を倍にせず`--scale 2`で作る
- 論理幅は、ブログ本文など実際に表示する幅へ近づける
- 予定表示幅へ縮小した後も最小文字サイズを原則14px以上にする
  - `縮小後の文字サイズ = HTML上の文字サイズ × 予定表示幅 ÷ 論理幅`
- 寸法はプリセットではなく、配置済み要素の外接矩形から決める
- 外接矩形へ外周余白を加え、文字、線、境界が切れない最小のキャンバスにする
- 最外周要素の外接矩形は、原則としてキャンバスの幅と高さの70〜94%へ収める
- 余白を削って要素数を増やさず、要素が多い場合は図を分割する
- 6個を超える横並びノードは、2段化または分割を優先する
- 高さを固定したまま説明文を増やさない
- 16:9は、ユーザーがスライド用の寸法を指定した場合だけ選ぶ

## 文字

日本語と英数字が混在しても字幅が安定するローカルフォントを使う。

```css
font-family:
  "Avenir Next", "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic", "Meiryo", sans-serif;
```

| 役割               | 目安          |
| ------------------ | ------------- |
| 図中の中心ラベル   | 24〜30px、700 |
| 主ノードのタイトル | 20〜26px、700 |
| 主ノードの説明     | 16〜20px、500 |
| 注釈               | 16〜18px、500 |
| 小さなラベル       | 16px、700     |

- 1行の日本語は概ね12〜20文字に抑える
- タイトルを2行にする前にカード幅や短い正式表記を検討する
- 英語の製品名、API名、識別子の途中で改行しない
- 文字間隔を広げすぎない
- 図全体のタイトルを置く場合でも、ノードより大きな見出し帯を作らない

## 配色

白文字を載せる主カードには、十分に暗い有彩色を使う。
白、灰、黒だけで図を完成させない。

| 色相   | Strong    | Tint      | Tint上の文字 |
| ------ | --------- | --------- | ------------ |
| Blue   | `#1D4ED8` | `#DBEAFE` | `#1E3A8A`    |
| Teal   | `#047857` | `#CCFBF1` | `#134E4A`    |
| Amber  | `#B45309` | `#FFEDD5` | `#78350F`    |
| Violet | `#6D28D9` | `#EDE9FE` | `#4C1D95`    |
| Rose   | `#BE123C` | `#FFE4E6` | `#881337`    |

| 補助用途  | 色        |
| --------- | --------- |
| Indigo    | `#4338CA` |
| Deep blue | `#1E3A8A` |
| Connector | `#64748B` |

- 既定は主色1色と、その同色相のStrong、Tint、境界色を使う
- 分類、段階、状態、責任の違いがある場合、または参照構成が複数色の場合は、暗さを揃えた2〜4色を使える
- 意味のない虹色配色は避けるが、白・グレーのカードへ1点だけ色を添える構成も既定にしない
- 単なる順序を1色で表す場合も、無彩色ではなく有彩色の濃淡、番号、線、位置を使う
- 状態の良し悪しを色相だけで示さず、ラベルやアイコンを併用する
- 白とInkは可読性のための文字色として使い、主要カードの塗りには使わない
- 主カードの本文は白、注釈は対応するTintとTint上の文字色を基本にする
- 薄い色の上に白文字を置かない
- Roseは通常の順序より、警告、異常、監視など赤系の連想が妥当な対象へ優先する

## カード

- 主ノードは`rounded-xl`または`rounded-2xl`を基準にする
- 主ノード内の余白は14〜24px
- 小さなラベルや補足の余白は8〜16px
- 同列の高さは比較に必要な範囲で揃え、短い内容へ過剰な高さを与えない
- 影は既定で使わない
  - 奥行きや前後関係を表す場合だけ、`rgba(15, 23, 42, 0.08)`前後の弱い影を1種類使う
  - 影を使う前に、1pxの境界線または色面だけで区別できないか確認する
- `text-shadow`、CSSアウトライン、`-webkit-text-stroke`は使わず、必要な輪郭は境界線で表す
- `text-decoration`と`text-emphasis`は使わず、必要な線や記号は独立した要素で表す
- `contain: paint|content|strict`、`content-visibility`、旧式の`clip`、`border-image`、`-webkit-box-reflect`は使わない
- 影を付けた要素とその祖先は`transform`や`zoom`で変形しない
- 境界線と影を同時に強くしない

## コネクター

- 矢印はカード間の専用グリッド列または背面SVGへ置く
- 線幅は2〜4px、色は`#64748B`
- 矢印の先端は接続先カードへ触れさせず、6〜12px離す
- 一方向の系列では全矢印の長さ、太さ、位置を揃える
- 双方向、非同期、任意経路は線種またはSVG内に直接描いた矢じりで区別する
- SVGの`marker-start`、`marker-mid`、`marker-end`は使わない
- CSSの`::marker`は使わず、必要な箇条書き記号は配置を制御できる要素として直接描く
- Unicodeの`→`や`↓`ではなくインラインSVGを使う

## アイコン

- 既定は0個とし、必要な場合も1カードにつき1個までにする
- 役割を補助する単純な線または面のアイコンを使う
- 24×24の`viewBox`を持つインラインSVGにする
- 装飾専用なら`aria-hidden="true"`を付ける
- ブランドロゴを推測で描かない
- 文字だけで識別できる場合は置かない
- 全ノードへ同じ密度で付ける必要はない

## 内容量

### 横方向の工程・変遷

- 3〜5段階
- 各ノードはタイトル1個、説明1行を基本にする
- 補足はノード内の短い1行または直下の小さなラベルにする
- 注釈を独立カードにするのは、全段階で対応関係を比較する場合だけにする

### 比較

- 3〜4選択肢
- 比較軸は3〜5個
- 長い文章ではなく、名詞句または短い判断文を使う

### レイヤー

- 3〜5層
- 層名、役割、代表コンポーネントを分ける
- 依存方向を矢印で示す

### フロー

- 5〜8ステップ
- 条件分岐は2方向まで
- 長い例外処理は別図へ分ける

## 避ける表現

- キャンバス全面の白背景
- 白、灰、黒だけで構成したカード群
- 淡い紫のグラデーションを全体へ敷く
- 意味のない装飾円、光彩、ノイズ
- 図全体を囲う大きなパネル
- 独立した見出し帯、キッカー、スライド番号
- 不要な16:9キャンバスと広い上下余白
- 大きな角丸と浮遊感のある影を全ノードへ付けること
- 小さなカードを大量に並べる
- 本文と同じ太さ、同じ大きさのタイトル
- 矢印がカードや文字の背後を横切る配置
- 同じ情報をカード、注釈、凡例で重複させる構成
